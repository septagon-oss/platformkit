# v3.0.0 — what the next major after this line owes

[The compatibility rule](../COMPATIBILITY.md) refuses a removal on a frozen line, and the
line this record freezes ([scripts/baselines](../../scripts/baselines/)) publishes the
exported surface as it stands at the freeze commit. So the earliest major that may remove
anything below is the one after that line, and this file names it.

**Writing a name here authorises nothing.** On the v2 line a removal is refused by
`make check-apidiff` whatever this file says; the file is the reading list for the review
that happens when the next major opens, and it is what makes the deprecation window
checkable by a person when no tool reads a `// Deprecated:` comment.

| Identifier | Deprecated on | Replacement | Removal authorised in | Migration documented in |
| --- | --- | --- | --- | --- |
| `modules/auth.TopazOptions` | the v1.1 line, at the freeze commit | `topaz.Options` from `kit/tenancy/providers/topaz` | v3.0.0 | the provider's own package, `kit/tenancy/providers/topaz`; the alias delegates to it today |
| `modules/auth.NewTopazPolicy` | the v1.1 line, at the freeze commit | `topaz.New` from `kit/tenancy/providers/topaz` | v3.0.0 | the same provider; the function forwards to it today |
| `modules/notification/contracts.Notice.Email` | the v1.1 line, at the freeze commit | `Notice.Wants: contracts.WantsEmail` | v3.0.0 | the field's own doc comment; `Ceiling` folds the flag into the asked-for set today |

Every row is a `// Deprecated:` comment in the tree carrying a replacement that works and
is the shape the kernel wants a caller to write. A row is added when a deprecation lands
and removed when the major actually cuts it; a row whose removal someone reverts is a row
this file loses, not one it explains.

Anything not on this list stays. A removal that is not on it is a change that has not been
deprecated for a minor, and the rule refuses it in the major as well as on the line.
