# v3.0.0 — what the next major after this line owes

[The compatibility rule](../COMPATIBILITY.md) refuses a removal on a frozen line, and the
line this record freezes ([scripts/baselines](../../scripts/baselines/)) publishes the
exported surface as it stands at the freeze commit. So the earliest major that may remove
anything below is the one after that line, and this file names it.

**Writing a name here authorises nothing.** On the v2 line a removal is refused by
`make check-apidiff` whatever this file says; the file is the reading list for the review
that happens when the next major opens, and it is what makes the deprecation window
checkable by a person when no tool reads a `// Deprecated:` comment.

The two `kit/rest` rows ask a migrating author to move one option and let the other stay. A
command guard already written as `CommandOptions.Auth` may stay there: the two guard fields are
two words for who may run the command, and the mount refuses only a pair that answers that
differently. The collection route has no such agreement, because `false` is how "the row's
route" and "nothing said" are both spelled, so a `Collection: true` sitting in
`CommandOptions` has to be written as `CommandSpec.Collection`.

Which callers could still reach either refusal is a count of the tree, not a rule, so it is kept
here rather than in the code that states the rule. Taken at `8f975f9`, 28 mounts still take the
positional pair: 23 of them in `modules/task`, `modules/user`, `modules/content`,
`modules/webhook` and `modules/decide`, and 5 in `kit/rest` itself — `history.go`'s restore and
the four writes of `translations_write.go`. No caller composes `Mount` or `MountResult` yet, so
none sits mid-migration with both spellings, and the adapter the positional pair runs through
clears the two `Options` copies, which is why neither refusal has reached a call site. The
number re-derives: `grep -rn "rest\.Command(\|rest\.CommandResult(" --include='*.go' . | grep -v
_test.go` lists the 23 outside `kit/rest`; the 5 inside it call the package's own `Command`
unqualified, from `history.go` and `translations_write.go`. Each module that migrates lowers the
total by its own share.

Every row is a `// Deprecated:` comment in the tree carrying a replacement that works and
is the shape the kernel wants a caller to write. A row is added when a deprecation lands
and removed when the major actually cuts it; a row whose removal someone reverts is a row
this file loses, not one it explains.

Anything not on this list stays. A removal that is not on it is a change that has not been
deprecated for a minor, and the rule refuses it in the major as well as on the line.

## Signed integers on the wire

Numeric int64 output is deprecated in favor of the selectable decimal-string
representation documented in [httpx](../../kit/httpx/README.md#exact-signed-integers).
After at least one published minor's deprecation window, the next eligible major
may switch ordinary JSON output and its OpenAPI schemas to string/int64.
Both string and number input remain supported. The owner must migrate and check
generated clients, their Accept configuration and the phone before that cutover.
This is a representation deprecation; Go int64 fields and `httpx.New` remain supported.
